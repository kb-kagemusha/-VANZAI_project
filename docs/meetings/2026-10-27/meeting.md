## 05 起床報告の期限をどう決めるか

### 適用中の起床監視：反映後の動き

現在の仮設定は「その日最初の勤務の開始時刻の3時間前」です。**集合時刻の独立した入力欄はまだなく、勤務開始時刻を基準にしています。** 集合が開始より早い案件があるか、本日の会議で確認します。

| 9:00開始の例 | 起こること（0.54.0反映・確認後） |
| --- | --- |
| 6:00：報告期限 | 未報告の本人へ、公式LINEで「起きました（起床報告）」ボタン付きの催促を送る |
| 6:15：運営への通知 | まだ未報告なら、通知を受け取る権限がありLINE連携済みの運営へ、案件ごとに未報告者をまとめて知らせる |
| 「私が連絡します」を押す | 押した運営へ電話の発信ボタンと結果ボタンを返し、ほかの運営へ対応者を知らせる。電話発信は運営が操作する |
| 別の運営も押す | 対応中の人を表示し、「代わりに私が対応する」で引継ぎできる |
| 誰も引き受けない | 10分ごとに再通知。現在の設定では勤務開始時刻で自動通知を終了する |
| 運営への通知後、本人が起床報告する | 通知先の運営へ「報告が届きました。連絡は不要です」と知らせる |
| 電話の結果を記録する | 「起床を確認した／電話がつながらない／現場へ連絡した／欠勤」を記録し、PC管理画面と共有する |

<aside class="callout warning"><strong>仮設定のまま運用を始める前に</strong><p>7:00開始なら本人への催促は4:00、運営への通知は4:15になります。早朝の当番と通知時間を決める必要があります。試験・実演のためテスト予定も通知対象です。運営用LINEの表示切替でテストを隠しても、自動監視の対象から外れるわけではありません。期限・通知間隔の変更は、現時点では開発による設定変更と反映が必要です。</p></aside>

**まず確認したいこと：連絡がつかない場合、勤務の何時間前から代わりの人の手配を始める必要がありますか。**

本人が間に合うだけの期限では、近くに住む人の欠員が分かるのが遅くなる場合があります。移動時間の精度だけでは解決しません。

### 移動時間の扱いを比較

| 案 | 運営・本人の手間 | 外部サービス費 | 注意点 |
| --- | --- | --- | --- |

### 追加提案：2つの期限の「早いほう」を使う

<div class="formula"><div><span>本人が間に合う期限</span><strong>集合・開始 − 移動 − 準備 − 余裕</strong></div><div><span>代わりの手配に備える期限</span><strong>集合・開始 − 連絡にかかる時間 − 手配の猶予</strong></div><p>起床報告の期限 ＝ 上の2つのうち早い時刻</p></div>

既存方針の準備時間は60分、移動の余裕は15分です。移動時間には両端の徒歩も含めます。集合時刻と勤務開始が別の場合は、どちらを基準にするか、登録方法を含めて確認します。

**例：9:00集合、移動30分、準備60分、余裕15分なら本人向け期限は7:15。連絡30分＋手配2時間を確保するなら、手配向け期限は6:30となり、早い6:30を採用します。** 数値は説明用です。代替要員が確保できることを保証するものではありません。

## 06 中止・連絡の運用ルール

中止・送付先除外の自動通知と、一部の日の中止は今後の実装です。以下は運用方針の確認用で、実装までは直接連絡で補います。起床監視の動きは、前章の0.54.0の説明をご確認ください。

| 場面 | 方針 |
| --- | --- |
| 一部の日の中止 | 通常操作は、その日の勤務開始の48時間前まで。それを過ぎる場合は、本人の了承を得た日時・相手などを責任者が記録する。開始済みの日は中止しない |
| 中止後の予定 | 運営の確定時点で中止日を予定から除外。日を減らすだけなら残日の再受諾は不要。単価・時刻・場所なども変わる場合は受諾を取り直す |
| 運営都合の中止 | 運営都合として理由を残し、本人都合と分けて集計する |
| 通知の確認 | 本人が「確認しました」を押す。通知の確認と、新条件への受諾は別の操作 |
| 確認期限 | **通知の登録時刻**を基準に固定する。通常は2時間後。0:00〜9:59の登録は「2時間後」と「同日10:00」の遅いほう。21:00〜23:59は翌日10:00。再送しても延長しない |
| 期限の調整 | 運営による変更は履歴を残す。勤務開始にかかる場合は開始前へ調整し、時間が残らなければ直接連絡が必要と表示する |
| 確認がない | 期限超過を運営画面とLINEで知らせ、その先は電話で確認する |
| 48時間未満の中止・送付先除外 | 確認期限を待たず、登録時点から「直接連絡が必要」と表示する。48時間ちょうどはこの即時判定の対象外 |
| 起床報告がない | 0.54.0反映後は、本人への催促から15分後に受信権限のある運営へ通知。「私が連絡します」で共有し、未対応なら10分ごとに再通知。仮設定は本日確認する |
| 運営への予定のまとめ | 前日18時と当日朝。朝の時刻は各自で設定する計画 |

<aside class="callout warning"><strong>今日の決定：48時間未満の例外操作を認める責任者</strong><p>候補は「管理者の役割だけ」「運営の特定メンバー」「運営全員」。誰でも操作できる方式は柔軟ですが、了承記録の品質と責任が曖昧になりやすいため、責任者と代行者を明示する案を推奨します。全体取消・送付先除外にも同じ48時間の操作制限を適用するかは、別途確認が必要です。</p></aside>

電話で了承が取れない緊急中止や、補償・請求・支払が関わるケースの判断は、この画面の操作ルールだけでは決まりません。連絡不能時の判断者と取扱いを、開始前の確認事項として残します。
