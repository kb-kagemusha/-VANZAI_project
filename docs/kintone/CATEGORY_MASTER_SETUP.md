# 案件カテゴリマスタ設定ガイド

## 概要
案件アプリのカテゴリ（大/中/小）はマスタデータから動的に読み込まれます。
ハードコードされた値は一切なく、すべて案件種別マスタ（app: 164）から取得します。

## マスタCSV構造

### フィールド定義
| フィールドコード | 名前 | 説明 |
|---|---|---|
| type_id | 案件種別ID | PT001〜PT049 など |
| name | カテゴリ名 | 表示名 |
| category_level | カテゴリレベル | major, middle, minor |
| parent_major | 親（大カテゴリ） | 中カテゴリの場合に指定。複数の場合は\|区切り |
| parent_middle | 親（中カテゴリ） | 小カテゴリの場合に指定 |

### カテゴリレベルの種類
- **major**: 大カテゴリ（親なし）
  - 例: J社_加熱式タバコ販促PR施策
- **middle**: 中カテゴリ（parent_majorに親を指定）
  - 例: 飲食店巡回2980円(小カテゴリ有), parent_major=J社_加熱式タバコ販促PR施策
- **minor**: 小カテゴリ（parent_middleに親を指定）
  - 例: 飲食渋, parent_middle=飲食店巡回2980円(小カテゴリ有)

### 複数親の指定方法
中カテゴリが複数の大カテゴリに属する場合、parent_majorに`|`で区切って指定:
```csv
PT011,商業施設/たばこ屋系(小カテゴリ有),middle,J社_加熱式タバコ販促PR施策|J社_紙巻きタバコサンプリングPR施策,
```

## front_dashboard.jsの動作

### 初期化フロー
1. `loadCategoryData()`: マスタからカテゴリデータを取得
2. `CATEGORY_OPTIONS`: レベル別にカテゴリ名を配列化
3. `CATEGORY_RULES`: 親子関係のマッピングを構築
   - `majorToMiddle`: 大→中のマッピング
   - `middleToMinor`: 中→小のマッピング
4. `initCategorySelects()`: select要素にオプションを設定

### カスケード動作
- 大カテゴリ選択 → 中カテゴリの選択肢が絞り込まれる
- 中カテゴリ選択 → 小カテゴリの選択肢が絞り込まれる
- 親カテゴリ変更時は子カテゴリの選択がクリアされる

## マスタデータ更新手順

### 1. CSVファイルを編集
[project_types_sjis.csv](../../kintone_app/project_types_sjis.csv)を編集:
```csv
type_id,name,category_level,parent_major,parent_middle
PT050,新規カテゴリ,major,,
PT051,新規中カテゴリ,middle,新規カテゴリ,
PT052,新規小カテゴリ,minor,新規カテゴリ,新規中カテゴリ
```

### 2. Kintoneにインポート
1. 案件種別マスタアプリ（ID: 164）を開く
2. 右上の設定 → ファイルからレコードを読み込む
3. CSVファイルを選択してアップロード
4. フィールドマッピングを確認して実行

### 3. フロント画面で確認
1. 案件アプリを開く
2. 「案件を登録」ボタンをクリック
3. 大カテゴリのドロップダウンに新規カテゴリが表示されることを確認
4. カスケード動作を確認

## トラブルシューティング

### カテゴリが表示されない
- ブラウザのコンソールでエラーを確認
- `loadCategoryData()`のAPI呼び出しが成功しているか確認
- マスタアプリのアクセス権限を確認

### カスケードが動作しない
- parent_major, parent_middleの値がname列の値と完全一致しているか確認
- category_levelの値が正しく設定されているか確認（major/middle/minor）

### 複数親が機能しない
- parent_majorの区切り文字が半角パイプ`|`であることを確認
- 前後にスペースが入っていないか確認

## キャッシュについて
`CATEGORY_DATA`はブラウザセッション中キャッシュされます。
マスタを更新した場合、フロント画面をリロードしてください。
