## 修正

| 問題 | 変更・仕様根拠 |
|---|---|
| 月次集計・皆勤判定がSQLite固有のstrftimeを使用 | 日付範囲条件に変更。YYYYMMと既存インセンティブのYYYY-MMを扱い、年・月を検証。仕様§3/13/18 |
| 皆勤判定が旧status=validを参照し、行数を日数としていた | active実績の異なる稼働日を数える。同日複数行、invalid、superseded、取消アサインを除外。仕様§6.3/10.2/18 |
| 担当者一覧・稼働者紐付け保存でWorkerが未定義、page/offsetが不一致 | モデルを読み込み、共通APIのoffset/limitへ統一。フロントの戻り値型も整合。仕様§6.1 |
| 案件通知表示のProjと、プッシュ失敗記録のloggerが未定義 | 正しいモデルとロガーを使用。仕様§14/16 |
| インセンティブ作成で存在しないマスタを指定するとNameError | RecordNotFoundExceptionを読み込み、既存の業務エラーを返す。仕様§18 |
| 再計算が請求対象時間0分を拘束時間で置き換える | 保存済みcalc_minutes_billableを使用。仕様§7/8 |
| force=Trueで確定帳票の実績を変更可能 | forceでも除外し、プレビュー件数も一致させる。帳票発行・承認・締めと共通の案件ロックを取得してから値を再取得。仕様§6.3/7.4/12 |
| デプロイが既存.envを読んでキーを自動追記 | 自動追記を廃止。既存設定はサービス起動・マイグレーションに使用するだけとし、手動で内容を取得・表示しない |
| OCR信頼度の文字列値を型として記述 | Literalへ修正。実行時の型ヒント解決も検証 |

既存モデル・列のみを使用するためDDL/マイグレーションは不要。
発行済み帳票・過去実績の一括修復や再計算は実行しない。
監査は既存のrecalculateイベントに件数・差額とforce_requestedを記録する。
通知作成の既存監査も維持する。
