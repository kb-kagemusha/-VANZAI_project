## 2. 補正事項

### R3-01 [P1 / A1のDDL確定前] 適用送付行と適用版を、必ず両方NULLまたは両方非NULLにする

対象：設計134–149行、A1-21c。

applied_delivery_idとapplied_version_idは両方nullable。現在の複合FKだけでは、片方がNULLの場合に所属確認を通過できる。

具体例：文書D1の適用行に、同じ稼働者の別文書D2の送付行L2を指定し、applied_version_idだけNULLにする。この場合、送付行と稼働者のFKは成立し、版を含む2つの複合FKはNULLを含むため所属を検証しない。

設計どおりの組合せを縮小したSQLiteで、foreign_keys=ONでもこの不正な行が保存されることを確認した。NULLの一致条件を追加すると拒否できた。

追加するCHECK：

```sql
CHECK (
  (applied_delivery_id IS NULL AND applied_version_id IS NULL)
  OR
  (applied_delivery_id IS NOT NULL AND applied_version_id IS NOT NULL)
)
```

既存の複合FKを置き換えるのではなく、CHECKを加えて組み合わせて使う。

追加試験：両方NULLは許可／正しい組合せは許可／片方だけNULLは両方向とも拒否／別文書・他人・別版の組合せを拒否。PostgreSQLのマイグレーション試験でも確認する。

### R3-02 [P2 / A1の既存LINE互換試験] offered_dates=NULLの旧送付行を受諾した場合を明示する

対象：設計107、277、284、375–376行、A1-15・A1-33。

旧送付行はoffered_dates=NULLとして予定生成の対象外にする方針だが、マイグレーションでは旧版が回答受付版になりうる。一方、受諾手順は一律に「dates=提示日の全部」の参加日状態を作り、適用送付行へ設定する。

旧LINEメッセージの受諾が届いた場合、提示日NULLを日付配列として処理して例外になったり、対象外だった旧データを予定へ変換したりしない分岐が必要。

推奨する互換処理：

- 旧送付行の受諾・辞退は既存の回答履歴として記録する。
- offered_dates=NULLなら、参加日状態・適用送付行・稼働予定は新規生成しない。個人の提示日を自由文から推測しない。
- 「あなたの稼働日」追加もNULLの場合の表示を分け、Noneや空の配列をそのまま送らない。
- 新方式へ移す必要があれば、日程を明示した修正版の確定・受諾で処理する。

旧送付行自体を受付対象外にする方式を選ぶ場合は、500ではなく明示した案内を返す。ただし、既存のLINE回答を維持する方針・A1-33との整合を確認する。

追加試験：旧確定・未回答の送付行を残してmigration→古い受諾ボタンを押す→正常応答し、旧回答は記録されるが予定はできない。再送・辞退・送付文のNULLも確認する。

### R3-03 [P2 / 再構築の試験] 発注終了後の旧superseded行の分類をそろえる

対象：設計255–264行、計画§7.4の回答受付版取消。

現在有効な予定集合を元データだけで決める方針は反映された。一方、集合外の歴史行の状態には補足が必要。

v1受諾→v2受諾でv1がsuperseded→v2を取消して適用送付行NULL、という場合、手順2の「それ以外はcancelled」に従うと旧v1のsupersededもcancelledへ変わる。上位計画では、回答受付版の取消時はsuperseded以外を取り消すことになっている。

補正：現在の有効予定集合の復元と、過去行のsuperseded/cancelled分類を区別し、元データ・受諾や適用変更の履歴に基づく規則を決める。少なくとも、発注終了を理由にすでに置換済みだった旧版の行まで一律に取消へ塗り替えない。

追加試験：v1受諾→v2受諾→v2取消で、v1はsuperseded、v2はcancelled。再構築しても分類が変わらず、active/changingは残らない。

この点は現在の勤務の復活を示すものではなく、履歴状態と上位仕様の整合の補足である。適用送付行を追加した中心方針を撤回する必要はない。
