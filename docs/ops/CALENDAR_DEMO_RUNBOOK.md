# 2026年10・11月のカレンダー確認データ（DEC-083）

## 画面で確認する

1. カレンダーで10月または11月を開き、「テストも表示」を押す。
2. 出勤可能日／イベントごと／稼働者ごと／参加カレンダーを切り替える。月とテスト表示の選択は引き継ぐ。
3. 色はカテゴリーごと。研修だけは専用色、業務＋研修は業務色。ピンクの「テスト」ラベルで正式な発注と区別する。
4. 全体管理者の「依頼書の金額確定」で「テストも含む」にチェックし、金額を入力する。履歴を残して変更できる。テスト金額は正式月次請求に入らず、通常の未入力バッジにも入らない。

## データ投入（今回のみ・明示実行）

コードのcommit/push後、既存のデプロイ手順のみを使う。

```bash
bash /var/www/vanzai/scripts/deploy/02_app_deploy.sh
bash /var/www/vanzai/scripts/deploy/02_app_deploy.sh --calendar-demo-preview
bash /var/www/vanzai/scripts/deploy/02_app_deploy.sh --calendar-demo-apply
```

通常モードでコード反映後、preview/applyを実行する。preview/applyはデプロイ済みコードによる単独運用モードで、git取得・ビルド・マイグレーション・API再起動・cron更新を行わない。
previewは既存サンプルの文書番号・案件名・区分の3項目だけ表示する。通常依頼の内容を出さない。
applyは既存サンプルをテストに変換し、各月15件を作成する。通常デプロイでは実行しない。新スクリプトへ自己更新する場合もオプションを保持する。

- 対象: 名称にサンプル/テスト/sample/dummy/デモを含む既存依頼。請求書明細で使われていたら変更を停止し、トランザクション全体をロールバックする。
- 旧PDFは保持し、テスト表示版を別キーで保存する。変更前のキーは監査ログから追跡できる。確定内容のスナップショットと版は変更しない。
- 新規依頼は全件テスト。データセットキー`calendar-demo-202610-v1`を取引相手メモに保存し、再実行で二重作成しない。
- 稼働者は既存の有効・LINE未連携のダミーを利用する。タグなしの人に新人/担当タグを付け、可否は未登録日だけ補完する。既存入力は保持する。
- 参加状態はデモとして保存し、送付状態はunknownとする。送信成功は記録しない。実送信・LINE連携・稼働予定のLINE通知・実績・請求・支払は作成しない。
- 監査: `calendar_demo_created/reclassified/pdf_reclassified/worker_tags/seeded`。金額保存は`order_billing_amount_confirmed`に`is_test`を含める。
- 後片付けは通常の依頼書の一覧除外で行い、物理削除しない。可否の補完行はnotesのデータセットキーで識別できる。

必要人数と不足表示は保留。テスト請求書の生成・発行は今回の対象外。
