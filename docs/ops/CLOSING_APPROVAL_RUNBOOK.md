# 締め申請・二者承認の運用

本締めと締め解除は、申請者とは別の認証済み権限者が承認してから実行する。仮締めは従来どおり直接実行する。

## 手順

1. 申請者はダッシュボードで対象月と案件を確認し、理由を記入して「本締めを申請」または締め解除の申請を行う。
2. 申請受付の表示後、締め状態は承認まで変わらない。別の権限者へ確認を依頼する。
3. 承認者は自分のアカウントでログインし、「締めの承認待ち」の案件・期間・操作・理由を確認して承認する。
4. 完了後に締め状態と監査ログを確認する。操作の失敗は申請を確認待ちのまま残す。

本人は自分の申請を承認できない。権限のない人、無効なユーザー、期限切れ、状態の変わった申請は承認できない。

申請の期限は24時間。誤った申請は取消・却下する。期限切れ後は新しく申請する。同じ案件・月・操作の確認待ちは1件にする。

解除は合計2回まで。既存の再締め期限（仮締め解除7日、本締め解除3日）を守る。発行／承認済みの明細に含まれる実績は、解除しても通常CSVで置き換えず訂正手順を使う。

## API

- POST /api/closing/hard、/soft/release、/hard/release: 202の申請受付。状態変更の完了ではない。
- GET /api/closing/approvals?period_key=YYYYMM: 権限で絞った確認待ち。
- POST /api/closing/approvals/{id}/approve: 別本人による承認・状態変更。
- POST /api/closing/approvals/{id}/reject: 取消・却下。

外部API利用者は、旧approver引数に名前を指定する方式を承認済みと扱わない。24時間以内に権限者本人の認証で承認APIを実行する。
