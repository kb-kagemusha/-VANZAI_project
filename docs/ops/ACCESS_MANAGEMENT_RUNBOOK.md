# ログインID・役割・権限管理

仕様正本: DESIGN_SPEC_v0.3 §5/16、DEC-056。

## 管理者が行う操作

1. 全体管理者のIDでログインし、メニューの「ID・権限管理」を開く。
2. 「ログインID」でID、表示名、メール、初期パスワード、役割を入力して作成する。
   同じID・メールは再利用できない。パスワードは8文字以上・UTF-8で72バイト以内。
   初期パスワードを本人に安全な方法で伝え、本人のプロフィールから変更してもらう。
3. 役割を変える場合は一覧の「権限・状態を変更」を開き、役割・有効/無効・理由を保存する。
   退職・利用停止は無効化する。IDの物理削除はしない。
4. 閲覧できる画面を変える場合は「役割ごとの権限」で対象役割を選び、閲覧チェックを変更して理由を保存する。
   編集・生成・承認は別の権限。編集を選ぶと同機能の閲覧も選ばれ、閲覧を外すと関連操作も外れる。
   変更は**同じ役割の全ID**に適用する。個人別の例外設定・任意の新しい役割の追加は今回の対象外。
5. 「初期設定を選び直す」はチェックを初期状態へ戻す。理由を入れて保存すると反映される。

## 初期設定と保護

| 役割 | 初期の範囲 |
|---|---|
| 全体管理者 | 全機能とID・権限管理。管理者権限は変更不可 |
| 運用担当 | 案件・シフト・配置の編集、CSV取込、請求・支払の生成など既存の運用権限 |
| 経理担当 | 案件等の閲覧、請求発行、支払承認、締めなど既存の経理権限 |
| 現場管理者 | 全案件・シフト・配置・実績の閲覧。請求・支払・単価・経費・監査は非表示。CSV提出は従来どおり担当案件に限定 |

- 既存usersのrole/is_activeを使用する。既存ID・パスワードは移行で書き換えない。
- role_access_policiesに設定のある役割だけ、保存した権限セットを使う。設定がなければ既存の既定値を使う。
- スタッフ用worker役割は既存のモバイル用途を維持し、この画面の新規ID作成では選ばない。
- 全体管理者の全権限を固定し、自分自身の降格・無効化を拒否する。
- APIはリクエストごとにDBの役割・有効状態・権限を確認する。既存トークンでも次のリクエストから有効。
- 画面は30秒ごととウィンドウ再フォーカス時に再確認し、権限変更時は業務キャッシュを破棄する。表示済み情報を後から回収することはできない。
- 閲覧を許可していない機能はメニューと直接URLの両方で拒否する。ダッシュボード非表示なら最初の許可された画面へ移動する。
- 単価権限がない利用者へ実績・配置一覧の単価を返さない。銀行口座APIには支払閲覧権限も必要。
- 帳票確定後の変更禁止、締めの二者承認などの業務上の制約は権限を付けても維持する。

## 監査と確認

- USER_CREATED: ID作成。パスワード・ハッシュは監査データに保存しない。
- USER_ACCESS_CHANGED: 役割・状態の変更前後と理由、実行者。
- ROLE_PERMISSIONS_CHANGED: 役割の権限セットの変更前後と理由、実行者。
- API: `/api/access/users` (GET/POST)、`/api/access/users/{id}` (PUT)、`/api/access/roles` (GET)、`/api/access/roles/{role}` (PUT)。すべて全体管理者専用。
