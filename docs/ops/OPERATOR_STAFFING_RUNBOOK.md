# 日別人数と参加者の最終確定

仕様根拠：DESIGN_SPEC_v0.3 §3・5・6・16、DEC-131〜134。

1. 新しい依頼書で「運営が人数調整して参加者を確定する」を選び、日程・候補者を入力して依頼書を確定する。既存の依頼書は従来方式のまま。改訂で方式を変更しない。
2. 詳細の「参加者・日別人数を確認」から、案件・日付ごとの上限人数を保存する。時間帯別には分けず、同じ人は同日同案件で1人。上限未設定の募集はLINEへ送れない。
3. 依頼書を送る。本人の参加可能回答は「運営確認待ち」。予定の画面に未確定と表示し、参加OK・起床監視・報酬見込みへ含めない。
4. 回答者から参加者を選ぶ。「確定内容を確認」後、「この内容で確定・通知する」で確定する。本人の追加承認は不要。同日の別案件で確定済みの人は選べない。正式とテストの予定は重複判定を分離する。
5. 上限まで確定した日は募集を終了し、選定者へ確定連絡、見送り・未回答者へ終了とお礼を送る。参加不可回答者にはその場の受付返信だけで、終了通知は省略。部分確定で空きが残る日は募集を続ける。上限未達で終了する場合は理由を記録する。
6. 通知は確定保存後に最大20件を処理する。残り・失敗件数があれば画面で確認し「未送信・失敗分を送る」で処理する。失敗を無制限に自動再送しない。同じ決定・人・日・種類の通知は1件だけ保存する。応答不明の再送は同じLINE再試行キーを使い、23時間を超えたものは自動送付対象から外す。

テスト案件の募集・確定・終了通知は、起床状況の「テスト通知を設定」と同じ期限付きスイッチで制御する。初期オフを維持。停止中・有効化前の結果通知は省略し、後でオンにしてもまとめて送らない。直接の回答への返信は画面・トークで受付を示す。従来方式の手動依頼書送付の挙動は維持する。

改訂前の運営確定は同じ系列・引き続き提示する日付と候補者に限り保持する。新しい内容への回答待ちは従来の変更確認として扱う。取消・削除済み・古い版の確定操作と通知は拒否または取消扱い。発行済み請求額はこの機能で再計算しない。

監査：staffing_limits_changed、staffing_decided、staffing_notice_processed、既存の参加回答・worker_schedule_entries_rebuilt。移行：20261027d001。戻す場合も決定・送信履歴を消さず、前進マイグレーションを使う。
