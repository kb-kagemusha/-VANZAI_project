# 欠員と代替人員の手配

仕様：DESIGN_SPEC_v0.3 §3・5・10・11・16、DEC-131・133〜135。

管理画面の起床状況、または公式LINEの運営画面から操作する。LINEの未報告通知の「別人員を確保する」も同じ画面を開く。現在のUserにorder_readとorder_writeが必要。閲覧だけの運営は手配状況を確認する。

1. 対象の稼働者・案件・日付を確認する。同日に複数の案件がある場合は対象を選ぶ。欠員理由を記録し「欠員として、この日の予定から外す」で確定する。他の日の予定、元のPDF・回答・実績・会計額は残す。
2. 同日の別案件に確定予定がない、出勤不可以外の稼働者から打診先を選ぶ。可否未登録・要相談・時間条件を確認し、LINE未連携の方は選ばない。欠員1名ごとに1枠。複数の欠員はそれぞれ手配する。
3. 日本時間の回答期限を指定する。現在より後、勤務開始までの時刻にする。「打診する内容を確認」から案内と宛先を確認し「この内容で募集を作成」。この時点ではLINEを送らない。
4. 「募集の内容・送付先を確認」で今回の依頼書内容と送付先を確認し、「この内容で募集のLINEを送る」。最大20名ずつ処理する。送信済み・応答不明へは重ねて送らない。残り・失敗は記録を確認して再操作する。テスト通知オフのときは送信しない。
5. 回答は未確定。「参加者・日別人数を確認」で引受可能と答えた方を選び、最終確認して確定する。確定者の予定を作り、元案件の日別人数へ合算する。先着順で自動確定しない。別の代替募集で確定した方に誤って見送り連絡を送らない。
6. 選定者へ確定と急な依頼の引受へのお礼、見送り・未回答者へ募集終了とお礼を送る。参加不可回答には受付時だけ返信し、終了通知を省略する。詳細と再送はOPERATOR_STAFFING_RUNBOOK.md。

募集前に本人の復帰を確認した場合は、理由を入力して「欠員を取り消し、元の予定を戻す」。他案件・人数上限を再確認する。募集を始めた後や代替確定後の復帰は直接戻さず、運営が参加者と実績を確認する。募集を誰も選ばず終了したときは、理由を保存してから候補を選び直せる。

勤務開始後・途中交代は自動差替えの対象外。本人指定により、運営が個別確認して実績・請求を扱う。半日・欠勤の金額をこの手配から推測しない。対象は依頼書から生成する予定で、別に登録した配置・実績を案件名の一致などで推測して取り消さない。

元案件を取り消すと関連募集も停止する。代替募集の文書は元案件の手配記録として保持し、独立した通常請求の候補には含めない。発行済みの請求明細・PDFや金額を自動再計算しない。

保存：staffing_vacancies（対象予定・案件・日付・元人員・理由・状態・版）、staffing_recruitments（欠員と代替募集系列の対応）。移行20261027e001。監査はDEC-135参照。通知スイッチはテストの募集・確定・終了にも適用し、停止中の通知を後からまとめて送らない。
