# 確定実績による1人日請求（0.56.1）

1. 依頼書の金額確定から「1人日単価で計算」を開く。実績が登録された案件を明示選択する。同じクライアントの案件だけを選べる。案件名からの自動対応は行わない。
2. 稼働者への支払単価と別に、請求の基本単価を入力する。曜日で異なる場合は変更する曜日だけ入力する。月曜0～日曜6で管理し、祝日の自動判定はしない。
3. 単価を保存して、日別の確定実績人数・氏名を確認する。同じ人・案件・日は1人日。無効な実績、取消配置は除外し、要確認実績があれば確定できない。
4. 半日などは人数を自動で減らさず、日別の調整額（減額はマイナス）と理由を入力する。注意書き・インセンティブ条件の文章は計算に使わない。実績0人の日は確認チェックと記録メモが必要。
5. 請求月・インセンティブを確認し、運営の確認チェック→最終確認→金額確定。日別明細、実績ID、氏名、単価版、調整根拠を履歴として固定する。インセンティブ空欄は請求書作成を保留する。
6. 月次請求書の下書きを作成し、日別小計と総額を確認して発行する。PDFも日別明細から作成する。

## 変更・重複・締めの扱い

- 実績や単価が変わったら、保存済み金額は残し、発行前に再確認を求める。下書き作成後に変更した場合は発行を止め、下書き取消後に再確認する。
- 既存の総額方式・発行済みPDFを自動変更しない。総額方式からの切替は旧額との差額を表示する。一度1人日方式で確定した同じ版は、日別画面から変更する。
- 確定済みの実績案件・月が締め済みなら、再計算・単価変更を止める。既存の締め解除・訂正手順を用いる。発行済みは上書きしない。
- 同じ実績案件・日付を別の依頼で請求できない。実績からの従来請求経路とも、発行時に重複を確認する。実績案件の誤選択を訂正したときは旧履歴を残し、未発行の旧対応だけを解除する。
- テストは通常の請求候補から除外。テストで計算しても正式請求書には入れない。代替募集の人数は元案件の実績として請求し、代替募集を独立請求しない。

## 権限・監査・確認

- 現行の依頼書請求と同じ全体管理者限定。LINE運営画面へ請求単価は公開しない。
- 監査：order_billing_daily_rates_changed、order_billing_daily_amount_confirmed、order_billing_actual_claim_released。既存の金額確定・請求書作成／発行監査も保存する。
