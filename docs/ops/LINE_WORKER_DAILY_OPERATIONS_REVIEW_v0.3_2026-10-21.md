## 1. 結論と前提

**前回のV2-01〜07は、計画上の対応として解消したと判断する。A0・A1の構成を再設計する重大な不足は今回見つからなかった。**

運用開始前で、依頼書をすべての予定の起点にするという新しい前提を採用する。既存予定の移行・併存を、引き続き必須課題として要求しない。稼働予定の直接編集禁止、staff-mobileとの役割分担、回答受付版、文書ロック、変更確認中の監視、除外日、報告日、ページングの方針は整合した。

§11の該当する業務判断を確定してDECISION_LOGへ記録すれば、A0・A1の詳細設計・DDLへ進める。以下の補足は実装設計と受入条件へ反映すればよく、全面改訂を求めるものではない。A2やTrack Bの課題を理由にA0・A1全体を止める必要はない。

静的な文書・現行コードの照合であり、実装の合格判定ではない。計画書に記された別の対話のユーザー回答について、原文の再確認はしていない。原計画書、コード、前回レビューは変更していない。

## 2. 実装設計で補う点

### V3-01 [P2 / A0公開前] A0で公開する6パネルの応答をそろえる

対象：計画55–56、285–288、414–415行。

A0でリッチメニューを設定する一方、①起床・⑤依頼書・⑥予定の機能はA1で実装する。A0の受入条件は②③④の「準備中」しか確認していない。A0を先に公開すると、残りの3つは現行の未知ポストバックとして無応答になるおそれがある。

修正案：A0単独で公開するなら6パネルすべてを「準備中」の応答にする。A1の機能公開時に①⑤⑥を有効化する。あるいはメニューをデフォルトへ適用する時期をA1公開時と明記する。Q21で⑤を後送りする場合も、⑤は「準備中」のままにする。

受入例：A0だけが反映された状態、A1反映後、⑤を未導入にした状態で、6パネルすべてが意図した応答を返す。

### V3-02 [P2 / ⑤をA1へ含める場合] PDFの再発行と、未受諾新版の閲覧条件を明記する

対象：計画323–327、427行。

既存PDFトークンは送信時に発行され、有効期間がある。長い勤務期間では、予定が残っていても元のリンクが期限切れになる。現行send_one()は受諾済みの送付先への再送を拒否するため、そのまま呼んで再取得する方式にはできない。

また、本文は「適用版を再照合」としながら、変更確認中では未受諾の新版を開けるとしている。受入条件の「本人の適用版だけ」では、この例外を表現できていない。

修正案：

- 本人の有効状態と、文書・版・送付先を確認した後に、新しい期限付きPDFトークンを発行する専用経路を設ける。既存の受諾状態・送信状態は変更しない。
- 閲覧可能なのは、本人の適用版、または本人が送付先になっている現在の回答受付版と定義する。後者は未受諾でも閲覧可とする。
- 受諾済み一覧への掲載条件と、未受諾新版を開く条件を区別する。取消・送付先除外・view_revoked・連携解除時の新規発行は拒否する。
- 発行済みURLは現行の期限付きトークン方式のままなら、URLを持つ人が閲覧できる。発行時の本人確認と、PDFを開くたびの本人確認は区別して記載する。

受入例：元のURLが期限切れでも再表示できる／受諾状態を変えない／本人宛ての未受諾新版を開ける／他人宛て・取消済みの版には発行しない。

根拠：`src/services/line_order.py` のsend_one()、read_shared_pdf()。期限付きURLを用いる方式自体を変更する要求ではない。

### V3-03 [P2 / A2前] 深夜勤務の除外は、開始時刻だけでなく実際の期限でも判定する

対象：計画294–297、331–342行。

0:00〜4:59の勤務を除外する方針だけでは、報告期限が前日になる全ケースを除外できない。たとえば開始05:00、移動180分、余裕180分なら期限は前日23:00。報告日をイベント発生日とするA1の規則では、その報告を翌日分の監視へそのまま適用できない。

修正案：既定の深夜除外に加え、実際のdeadline_atがwork_dateの前日へ落ちる場合もexcluded・要確認へ回す。これは例外を自動監視しないという既存方針の補完であり、A1の報告日を変える必要はない。

同日に02:00の除外勤務と10:00の通常勤務がある場合も定義する。除外勤務を要確認として残しつつ、10:00の通常勤務の監視まで失わせない。監視対象の勤務集合を決めてから、その集合の最も早い勤務を選ぶ。

## 4. 詳細設計へ引き継ぐ確認事項

以下は新しい業務判断を増やすものではなく、既定方針を実装に落とす際の確認事項。

- 除外日は勤務日を決める共通の展開処理へまとめ、予定・本文/PDF・単価のカバー確認で一貫させる。重複・範囲外・全日除外・期間変更時の残存除外日を検証する。旧確定版の本文/PDFを再生成しない。
- 回答受付版のFKは、別の文書の版を指せないようにする。稼働予定のworker・delivery・version・documentの組合せも検証する。行ロックは実装時に共通の取得順序へ固定する。
- staff-mobileをA1で公開しない措置は、ナビゲーションだけでなく直接URLの扱いも確認する。Q18の将来利用判断とは別に、A1の公開範囲を固定する。
- A2の論理通知は、作成時だけでなく送信・再試行時にも宛先の有効状態と権限を確認する。通知先設定を受信権限そのものとして扱わない。
- DESIGN_SPEC §4のplannedは現行assignmentベース。DECには「稼働者向け予定の正本を変更すること」と「会計用の予定集計への反映はB2以降であること」を区別して記録する。
- 開始前で移行不要という方針は、既存テストデータの物理削除を意味しない。A1の試験データと公開対象を識別する。
