# LINE運営画面と本人別メニューの運用（0.53.0）

## 利用開始

1. 公式LINEから運営登録を申請し、管理者が承認する。既に承認済みの人は再登録しない。
2. 管理者が「運営スタッフ登録・一覧」→本人の「内容確認・更新」を開く。
3. 「LINE運営画面のログインID」で**本人の既存管理画面ID**を選び、「IDの対応を保存」を押す。氏名の一致で自動紐付けは行わない。稼働者に直接紐付け済みのID・別スタッフのID・無効IDは選べない。
4. ID・権限管理で、対象の運営役割に起床状況/出勤可否/依頼書の閲覧権限があることを確認する。LINEの閲覧にも同じ権限を適用する。通知受信のwake_alert_receiveは別の権限。
5. 「LINEメニューを再確認」を押す。通常は1分以内の定期照合でも反映される。本人のLINEトークを開き、運営メニューを確認する。

既存Userとスタッフの対応が正しく1件なら追加設定は不要。対応が0件または複数なら、管理者の明示選択が必要。ID・役割・権限の自動作成/昇格はしない。

## LINEで使えること

- 起床状況: 日付ごとの報告あり/未報告、案件・予定時刻を閲覧する。未報告者を先に表示する。「最新の状況に更新」で取得し直せる。報告の有無は既存管理画面と同じ集計を使用する。
- カレンダー: 月と日を選び、「参加予定」または「出勤可否・配置」を表示する。許可された種類だけを表示する。氏名・案件名で絞り込める。
- 自分の登録情報: 自分の氏名・電話番号を確認する。編集は管理者へ依頼する。
- 兼務者の切替: 運営用の「稼働者用へ」と稼働者用の上部帯で往復する。LINE標準の切替を使う。稼働者登録がない運営専任者は3項目のメニューとし、押しても使えない切替を置かない。

稼働者側は、公開済みの既存メニューの操作だけを複製する。未公開の出退勤・売上等をこの変更で有効化しない。全員向けの既定メニューは変更しない。

## 利用できない場合

- 「管理画面IDの対応を確認」: 本人の有効な管理ロールのUserとスタッフを対応させる。稼働者ロールは運営画面を使えない。
- 「権限がありません」: 対応Userの最新の閲覧権限を確認する。管理画面で権限を外すと、LINEも次の取得から拒否する。
- 本人確認の期限切れ: LINEから画面を開き直す。セッションは30分で、管理画面や稼働者用トークンとは別用途。
- メニュー反映が再試行待ち: 「LINEメニューを再確認」で再試行する。定期照合は失敗回数に応じ最大60分の間隔まで待機する。
- ブロック解除/再友だち追加: 運営連携は自動復活しない。管理者が本人確認のうえ再連携する。古いメニューが残っても運営APIは利用できない。

## 保守

VPSでは通常の `02_app_deploy.sh` だけを使う。運用確認にも同じスクリプトの明示オプションを使い、秘密設定の値を表示しない。

| オプション | 動作 |
|---|---|
| `--operator-menu-status` | 公開状態、有効な連携数、ID対応が必要な人数、稼働者ロールの有効User件数を集計表示。個人情報/秘密値は出さない |
| `--operator-menu-sync` | 現在のUser/連携状態から再照合。本人がLINE上で選んだ有効な兼務メニューは上書きしない |
| `--operator-menu-publish` | 初回の画像/エイリアス登録と公開。既定メニュー不変を確認する。既に公開済みなら再作成しない |
| `--operator-menu-disable` | 個人別運営メニューを無効化し、所有する本人別割当だけを解除して既定表示へ戻す。失敗分は定期処理で再試行。登録・User対応・既定メニューは残す |

明示無効化後の通常デプロイでは勝手に再公開しない。復旧は公開記録と実際のLINE設定を確認してから行う。通常デプロイは初回未公開の場合だけメニューを作成する。

今回のマイグレーションは追加3表だけ。既存の登録/予定/金額は変更しない。履歴がある状態での削除downgradeは拒否する。

## 今回の対象外と実機確認

起床の自動催促・運営への氏名/電話番号通知はDEC-066/116の別工程で、今回のメニュー公開では開始しない。駅すぱあと導入条件を満たすまで自動催促を有効にしない。

公開後は本人のスマホで、運営専用画面・兼務往復・再起動後の表示保持を確認する。自動テストやLINE APIの割当確認は、実機で押せたことの代わりにはしない。
