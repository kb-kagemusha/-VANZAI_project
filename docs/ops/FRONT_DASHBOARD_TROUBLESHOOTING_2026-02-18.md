# FRONT DASHBOARD 障害調査・対策メモ（2026-02-18）

## 対象
- フロントページ（App174）
- `kintone_app/customizations/front_dashboard.js`

## 1) 症状: 支払明細作成時の稼働者選択にアルファベット羅列が表示される

### 事象
- 「見積/請求書、支払明細書の発行」→「支払明細書：稼働者」で対象者プルダウンに
  - `ID / ⚠ 名前未設定`
  - 英数字IDのみ
  が残る。

### 根本原因
- 候補生成 `fetchWorkerOptionsByIds()` が `fetchAllWorkers()`（`limit 500`）依存だった。
- 当月実績の `worker_id` が500件取得範囲外、またはマスタ未一致の場合に名前が引けず、ID表示へフォールバックしていた。

### 修正内容
- `worker_id in (...)` で実績対象IDを直接問い合わせる方式へ変更（100件チャンク）。
- 取得失敗時のみ既存の全件取得フォールバックを使用。
- マスタ解決できないID（`resolved=false`）は候補に残し、`（ダミー/マスタ未紐付け）` 表示で選択可能に変更。

### 期待効果
- 名前修正済みの稼働者は、候補表示に即時反映される。
- マスタ未紐付けIDでも、運用継続のためダミーとして選択して支払明細生成できる。

---

## 2) 症状: JS変更後にフロントボタン位置がズレる

### 事象
- ヘッダーメニューのボタンが折り返して、帯の下に落ちる/段落ちする。

### 根本原因
- 前回のレイアウト変更で `.vanzai-front-row` を `nowrap + overflow-x` にしたため、ヘッダー表示位置が以前の見え方（グラフアイコン横）から変わった。
- その結果、横スクロール運用が前面に出て、配置ズレとして認識されやすくなった。

### 修正内容
- `.vanzai-front-row` を `flex-wrap: wrap` に戻し、`overflow-x` 固定を解除。
- ボタン余白を従来値（`margin-right: 8px`）へ戻し、表示位置を以前の見え方へ復帰。

### 期待効果
- ボタンがグラフアイコン横の従来配置に近い表示へ戻る。
- ヘッダーでの横スクロール依存がなくなる。

---

## 再発防止ルール（運用）
1. フロントヘッダーにボタンを追加する場合
   - Kintone標準ヘッダーとの見え方を優先し、`wrap` 前提で配置確認する。
   - 追加時はデスクトップ幅で「グラフアイコン横」に収まるかを先に確認する。
2. 「ID→表示名」解決が必要な候補UIでは
   - `limit 500` の全件読み込みに依存せず、対象IDベース問い合わせを優先する。
   - 未解決IDの扱いを明示（今回: ダミー選択可）し、UI文言で区別する。
3. 変更後チェック（必須）
   - 幅狭表示でヘッダーが段落ちしないこと。
   - 「支払明細書：稼働者」で表示名が人名になること。
   - マスタ未紐付けIDは `（ダミー/マスタ未紐付け）` 表示で区別されること。

## 3) 症状: 何度修正しても画面が変わらないように見える

### 事象
- ローカル `front_dashboard.js` を更新しても、App174 画面に変化が出ない。

### 根本原因
- 今回の崩れは、表示版マーカーをヘッダーDOM通常フローに挿入したことで行高が押し下がったことが主因。
- 反映自体は行われており、問題は「表示位置」だった。
- なお一般論として、KintoneのJavaScriptカスタマイズは「アップロード → 保存 → アプリを更新」が必要。

### 確認手順（現在の判定）
1. App174を再読み込みする。
2. ブラウザ開発者ツールのConsoleで `BUILD_MARKER: FD-2026-02-18-DEPLOY-CHECK-01` が出力されるか確認する。
3. 画面右下に `FD FD-2026-02-18-DEPLOY-CHECK-01` バッジが表示されることを確認する（レイアウト非干渉）。
4. 出力やバッジが出ない場合は、App174 の JavaScriptカスタマイズに `kintone_app/customizations/front_dashboard.js` を再アップロードする。
5. 設定保存後、必ず「アプリを更新」まで実施し、Ctrl+F5 後に再確認する。

### 恒久対策
- 自動反映を使う運用では `.env` に `KINTONE_TOKEN_FRONT_DASHBOARD` を必須化する。
- 版表示を入れる場合は、通常フローに挿入せず固定バッジ等の非干渉レイヤーを使う。
- 画面確認時は、機能動作確認の前にConsoleの `BUILD_MARKER` 一致を先に確認する。
