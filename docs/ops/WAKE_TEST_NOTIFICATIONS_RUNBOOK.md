# テスト予定の起床関連LINE通知

DEC-128／Ver.0.54.3。初期状態は「送らない」。正式予定の監視や、運営LINE画面の「テストも表示」とは別の設定。

## 操作

1. 全体管理者で管理画面の「起床状況」を開く。
2. 上部の「テスト通知を設定」を押す。
3. 「送る（期限付き）」を選び、終了時刻を日本時間で入力する（初期候補は1時間後、最大24時間）。
4. 「設定を保存」を押し、一覧の「送る：○月○日○時○分まで」を確認する。
5. 終了前に止める場合は同じ画面で「送らない」を選んで保存する。期限が来れば、画面を閉じていても自動的に送らない状態になる。

全体で共有するため、ある管理者がオンにすると、テスト予定を対象に本人への催促と既存の受信権限を持つ運営への通知が有効になる。有効期間中の未対応の再通知は従来どおり10分ごと。実際の送信枠を使用する。

## テスト予定の作り方・対象

- オンにした後に**起床報告の期限（最初の開始の3時間前）**が来るテスト予定を用意する。たとえば10時にオンにして試すなら、13時より後に開始するテスト予定を用意する。
- オンにしたとき、既に期限を過ぎている予定は通知しない。停止中の催促や再通知をまとめて送らないための仕様。
- 同じ稼働者の同じ日に正式予定もある場合は正式を優先する。テストだけの稼働者・日で実演する。
- テスト通知は「【テスト】」付き。本人への催促、運営への未報告／再通知、引受共有、報告到着の知らせが設定対象。
- オフでも予定・報告は画面で確認できる。送信済みのボタンに対する本人への操作返信は維持するが、オフ中に他の運営へテストの引受共有は送らない。
- 同じ稼働者・日・通知種類・回の通知は再送しない。何度も同じ予定で通知を繰り返す機能ではない。
- 既にLINEへ送信済みの通知を取り消すことはできない。

## 競合・履歴

他の管理者が先に保存すると競合エラーになる。入力は残るので、表示された「最新の設定を読み直す」で確認してから選び直す。変更前後・実行者・日時は監査ログの`wake_test_notifications_changed`に保存する。期限切れの判定は保存された終了時刻から行う。

正式／テストの起床報告、対応記録、送信履歴は別の区分。画面でテストを表示したことだけでは送信は有効にならない。

## 保守確認（送信なし）

正規の読み取り専用コマンド:

```bash
bash /var/www/vanzai/scripts/deploy/02_app_deploy.sh --wake-monitor-status
```

`enabled`、`enabled_from`／`enabled_until`、`revision`、最終変更者・日時だけを表示する。監視の実行・LINE送信・設定変更・再デプロイは行わない。`--wake-monitor`は実際に正式通知を送る可能性があるため、状態確認の代わりに使わない。
