# テスト案件から正式版を作る（0.57.0）

目的はテストで用意した案件内容を再入力せず、正式な運用へ移すこと。元テストの区分や履歴を書き換えない。

1. 発注依頼書の作成済み一覧、またはテストの詳細から「正式版を作成・確認」を開く。取消・送付停止されていない最新の元案件を使う。代替募集は元案件から作る。
2. 日程・会場・業務条件・稼働者への報酬を確認する。日付別の募集上限はテストの設定を表示し、正式に使う人数を入力する。
3. 正式な発注元・担当者と、正式な送付候補を選び直す。候補は最初は未選択。テスト時の候補は参考表示する。氏名や案件名から「サンプル」を自動判定しないため、運営が実際のマスタを確認する。
4. 正式版の回答期限を今日以降で設定し、確認チェックを入れ、「確認して正式な下書きを作成」を押す。
5. 別番号の正式な下書きが開く。日程・条件・期限を編集・確認し、通常の手順でPDF確認、依頼書確定、送付先確認、LINE送信を行う。正式版作成だけでは送信しない。
6. 本人の回答後、正式版の日別上限を確認して運営が参加者を決める。テストの参加回答・選定・欠員・代替打診・起床報告・送信済み状態・確定金額は引き継がない。

## 保持・引継ぎ

- 元のテスト、PDF、回答、予定、会計履歴を保持し、正式版と関連付ける。通常の集計は正式を対象とし、テスト表示は既存の明示切替を使う。正式な予定は新たな本人回答・運営決定から生成する。
- 案件内容・勤務日・報酬条件を複写する。個人不参加日、電話済み記録、追跡担当、回答期限は自動コピーしない。
- 募集上限は確認した日付へだけ引き継ぐ。下書きで日程を変えたら、新しい日の上限を依頼書確定後に確認する。
- 請求の基本・曜日別単価は参考値として保持。全体管理者の請求画面で、正式な実績案件を選び直して保存する。テストの実績案件・人数・調整額・請求月・金額確定・請求書は持ち込まない。
- 同じテスト案件系列からは1件の正式版を作り、再操作や二重クリックは既存版を開く。作成後のテスト改訂も別の正式版を増やさない。正式版が取消・非表示でも自動で再作成しない。
- 作成した正式版の区分を再びテストへ変更できない。過去の日程は下書きで見直す。発行・締め済み帳票は変更しない。

## 権限・監査・確認

- 既存の発注依頼書閲覧・変更権限を利用する。LINE運営画面は欠員手配の範囲を維持し、この操作を追加しない。請求の参考単価は全体管理者限定で返す。
- 監査：order_test_formalized。元版・正式版・候補者・確認した上限・操作者・日時・下書き／送信なしを記録する。
- DB：order_formalizations。元文書・元版・正式文書を関連付け、元文書と正式文書の一意制約、案件系列の行ロックで重複を防ぐ。migration 20261028a001。
