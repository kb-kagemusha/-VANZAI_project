# ③-B / ③-C 結合試験の段取り（2026-10-24）

基準: 0.52.0 c05a52b。③-Cの実装は取り込み済み、web_replyは本番で無効のまま。
目的は、取消・送付先除外・新版辞退で開始済みの予定を失わず、将来の参加と通知を正しく終了すること。
担当: こちらが③-Bの共通処理と通知、もう一方が③-CのWeb辞退試験を用意する。同じファイルを同時編集しない。

## 1. 共通修正の入力と責任

- LineOrderService.decline_deliveryは変更せず、既存set_application/rebuild呼出しを維持する。
- 適用受諾を終了する時点の旧送付行ID・参加状態ID・終了日時を永続記録し、元の確定版から開始済みの日を判定する。
- 終了時点で開始済みだった分だけを残す。再構築時の現在時刻で残す日を増やさない。
- 履歴から予定を再生成できること。現在の派生予定のstatusだけに依存して残す実装にしない。
- 開始済み分に◆を付けない。将来分は取消。受諾履歴・原PDF・金額・締め済み会計を変更しない。
- D-11の一部日程中止は未決であり、この試験で仕様を確定しない。

## 2. 共通の試験データ

日本時間の固定時計を使用。例: 10/27・10/28・10/29各09:00開始の3勤務日を旧版で受諾し、10/28に終了する。
Web経路とトーク経路は別の依頼・稼働者で同じ条件を作る。DB更新・LINE送信は試験環境と偽のLINEクライアントを使う。

| 10/28 08:59 | 10/27 | 10/28・10/29 |
| 10/28 09:00 | 10/27・10/28 | 10/29 |

| 10/27 22:00開始〜10/28 06:00の夜勤、10/28 01:00に終了 | 10/27開始の夜勤 | 次回以降 |

## 3. 操作と合格条件

1. 最新版の取消・送付先からの除外・新版の辞退（トーク/Web）で上表を確認。
2. Webは試験用の公開設定だけweb_replyを有効にする。既存reply APIとIdempotency-Keyを使い、decline_deliveryへ到達すること。
3. 終了直後・10/30に時計を進めた後・再構築2回で同じ参加日と状態。未来だった10/29が復活しないこと。
4. 終了履歴から再構築しても同じ結果。現在行の保存状態が正本になっていないこと。
5. 本人のホーム・受託済み一覧で開始済み分が残り、◆や回答要求が出ないこと。管理カレンダーとの整合も確認。
6. 二度押し・同じキーの再送・トークとWebの同時回答で、受諾/辞退/終了履歴/受付通知が重複しないこと。
7. 中止とoutbox登録は同時保存。送信失敗でも中止は成立、再送結果と未確認者を運営が追えること。
8. 通知の「確認しました」は新条件への受諾・参加日の変更を起こさないこと（D-10採用済み）。
9. 元の受諾版・参加状態・確定PDF・金額入力・締め済み会計が変わらないこと。
