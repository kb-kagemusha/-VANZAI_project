# REVIEW_MERGE — v0.3 反映メモ（Gemini/Opus → DESIGN_SPEC_v0.3）

## 1. 反映方針
- 二重払い・二重請求・売上漏れの事故を最優先で潰す
- 運用担当が迷子にならないよう「手段」「期限」「責任者」「次の一手」を固定する
- 解除や再計算は必ずガードレール付きにする

## 2. Gemini指摘 → 反映
### 2.1 CSV Upsertキーに時刻を含めると二重化する
対応
- Upsertキー依存をやめ、replace_scope を標準に変更（9章）
- 旧データは status=superseded にして集計対象から除外（9.6）
- scope を project_month / project_day / project_day_worker で選べるようにした（9.5）
- 部分ファイル事故を検知する警告（行数や総時間の急減）を設計に追加（9.6）

### 2.2 canceled アサインに紐づく actual が残るゾンビ問題
対応
- actual に status（active/invalid/superseded）を必須化（6.2）
- canceled にする操作は actual がある場合ブロック（10.2）
- 例外として Admin のみ actual を invalid 化できる（10.2）
- 集計は actual.status=active のみ（6.3, 10.2）

### 2.3 丸め・休憩・hours優先順位が未定義
対応
- project に時間計算設定を追加し、デフォルト案を提示（8.1）
- system_first と csv_hours_first の2モードで挙動を明文化（8.2, 8.3）
- break_minutes 空の場合の扱いを rule で規定（8.2）

### 2.4 締め解除の「発行済みチェック」を厳格化
対応
- Soft Close / Hard Close を分離（12.1）
- Hard Close 後は unlock しない方針に変更（12.3）
- 再計算の対象から発行済み関連 actual を除外（7.4）

### 2.5 未決事項の追加（深夜、税、アサインなし実績）
対応
- 17章に意思決定対象として明示し、night_calc_mode と税方式を論点化（17章）

## 3. Opus指摘 → 反映
### 3.1 催促手段が未定義
対応
- デフォルト手段を「システム通知 + メール」として暫定確定（14.2）
- 催促テンプレを付録Aに追加（付録A）

### 3.2 締切までの日数の起算点が不明
対応
- 期限は営業日基準とし、営業日カレンダーを正本にする（14.1）

### 3.3 Site Managerの限定操作が曖昧
対応
- 許可/不許可を明文化（5.2）

### 3.4 差分アラートの後続アクションが未定義
対応
- 差分アラート一覧に「担当」「確認状態」を必須列として追加（13.1）

### 3.5 訂正と再発行の使い分けが曖昧
対応
- 基準を暫定で明文化し、Accounting承認を条件にした（11.2）

### 3.6 締め解除の乱用防止
対応
- 解除可能期間、回数上限、二者承認、再締め期限を追加（12.2）
- 解除履歴の表示項目をダッシュボード要件に追加（13.1）

### 3.7 CSV遅延の救済がない
対応
- provisional 扱いと後追い訂正のフローを追加（15章）

## 4. v0.3での意思決定ポイント（残課題）
- キャンセル料の暫定ルールを確定し、単価ルールに組み込む（17章）
- 税方式（行ごと/合計）を確定し、invoice_line の持ち方を決める（11.3, 17章）
- 深夜割増の保存方針（store_minutes を採るなら calc_minutes_night を必須化）を決める（8.1, 17章）
- アサインなし実績は v0.3 ではエラー扱い推奨か、例外ルールを定める（17章）
- shift_label をCSV必須にするか（運用負荷とのトレードオフ）（9.3, 17章）
