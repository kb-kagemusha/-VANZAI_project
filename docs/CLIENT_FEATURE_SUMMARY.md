# VANZAI 実装機能サマリー（クライアント向けキャッチアップ）

> **作成日**: 2026-07-24（最終更新: 2026-07-24）  
> **現在バージョン**: Ver.0.11.37（admin-web / staff-mobile 共通）  
> **本番URL**: 管理画面 `https://vanzai-portal.com` / スタッフ `https://staff.vanzai-portal.com` / API `https://api.vanzai-portal.com`

---

## 1. このドキュメントの目的

スプレッドシート中心の運用から、**案件・シフト・実績・請求・支払を一元管理する Web システム**へ移行したプロジェクトです。  
本書は、**いま何ができているか**をクライアント側でキャッチアップしやすいよう、画面・機能単位で整理したものです。

> **2026-07-24 重要**: 本番運用は **VPS（admin-web + staff-mobile + API）のみ**で完結します。Kintone 連携は本番コードから除去済みです。

詳細な変更履歴はルートの `CHANGELOG.md`、技術仕様は `docs/spec/DESIGN_SPEC_v0.3.md` を参照してください。

---

## 2. システム全体像

| レイヤー | 技術 | 役割 |
|---------|------|------|
| **管理画面**（admin-web） | React + TypeScript | 運用担当・経理・管理者向け。案件運用から請求・支払・締めまで |
| **スタッフモバイル**（staff-mobile） | React + TypeScript | 稼働者向けスマホ Web。出退勤・予定返信・稼働可否・経費・通知 |
| **API** | FastAPI + PostgreSQL | 認証・業務ロジック・PDF/メール・OCR など |

### ユーザーロール

| ロール | 主な利用者 | できること（概要） |
|--------|-----------|-------------------|
| admin | 管理者 | 全機能・マスタ・監査・締め解除 |
| ops | 運用担当 | 案件運用、CSV取込、請求/支払生成、仮締め |
| accounting | 経理 | 請求発行、支払承認、本締め |
| site_manager | 現場管理者 | 担当案件の参照・CSV提出 |
| worker | 稼働者 | スタッフモバイルのみ |

## 3. 管理画面（admin-web）— 実装済み機能

### 3.1 ダッシュボード `/dashboard`

- 未処理件数・アラートの一覧（次にやるべき作業が分かる設計）
- 月次の**仮締め / 本締め / 締め解除**（ガードレール付き）
- **月次一括生成**（請求・支払の一括作成導線）
- 予定確認の未返答・エスカレーション件数
- 支払明細の送信先未設定・未送信・送信失敗のサマリー

### 3.2 案件・シフト・アサイン運用

| 画面 | パス | できること |
|------|------|-----------|
| 案件一覧 | `/operations/projects` | 案件の登録・編集（取引先・現場・担当・期間・メモなど） |
| シフト枠 | `/operations/shift-slots` | 日付・時間帯・必要人数の枠作成・編集 |
| アサイン一覧 | `/operations/assignments` | 枠へのスタッフ割当、状態変更（仮/確定/取消）、一括更新 |
| アサイン回答監視 | `/operations/assignment-responses` | スタッフの予定返信未回収の監視、手動リマインド再送、エスカレーション通知 |
| 実績一覧 | `/operations/actuals` | CSV取込・打刻で確定した実績の参照 |
| 稼働可否カレンダー | `/operations/availability-calendar` | 全スタッフ横断の稼働可否を月/週表示（スキル資格バッジ付き） |

**アサイン運用の要点**

- 取消時は理由必須、取消からの復帰時も理由必須（監査ログに記録）
- 月次ごとの**選択セット**をサーバー保存し、一括状態更新に再利用可能
- 実績が有効なアサインは誤取消を API でブロック

### 3.3 CSV 取込 `/operations/csv-import`

- 実績 CSV のアップロード
- **洗い替えモード**（同日×案件×稼働者の範囲で二重化防止）
- 取込バッチ履歴・エラー内容の確認
- エラー差戻し用の文面を自動整形してコピー可能

### 3.4 請求・支払・経費

| 画面 | パス | できること |
|------|------|-----------|
| 請求書 | `/billing/invoices` | 生成・発行・PDF ダウンロード。見積/請求の帳票種別、担当者、件名、固定事務局費に対応 |
| 支払明細 | `/billing/payouts` | 生成・承認・支払済み更新・PDF・**メール送信**。worker / supplier / VANZAI担当者向け |
| 経費 | `/billing/expenses` | スタッフ申請の承認・却下・領収書確認 |

**支払明細の受取人種別**

- **稼働者**（worker）— 外注費・人工ベース
- **下請け・紹介者**（supplier）— 日額単価・人工単位
- **VANZAI 担当者**（vanzai_staff）— 全体統括（売上8%）、事務（固定＋日割）、プレイングマネージャー（配下人工×1,000円 or 個別固定額）

**請求書の拡張（管理画面で完結）**

- 帳票種別（見積書 / 請求書）
- クライアント担当者の宛先スナップショット
- 件名（例: `◯年◯月分_`）
- 固定事務局費の手入力

### 3.5 マスタ管理

| 画面 | パス | できること |
|------|------|-----------|
| 稼働者 | `/masters/workers` | 登録・編集、**振込先口座**（履歴・有効期間・マスキング表示） |
| マスタデータ | `/masters/data` | 取引先・現場・案件種別・役割・下請け、**VANZAI担当者**、クライアント担当者 |
| 単価 | `/masters/prices` | 売上単価・外注単価・単価ルールの登録・編集 |

### 3.6 登録申請（公開フォーム連携） `/operations/registration-requests`

外部から回収する登録情報を、**リンク＋PIN** で安全に受け付ける仕組みです。

| 公開フォーム | URL パターン | 用途 |
|-------------|-------------|------|
| 稼働者登録 | `/public/registrations/worker` | VANZAI 直契約スタッフの情報回収 |
| 個人（下請け/紹介者） | `/public/registrations/supplier-individual` | 個人事業主の下請け・紹介者 |
| 法人下請け | `/public/registrations/supplier-corporation` | 法人下請け |
| 紹介者身分証 | `/public/registrations/introducer-identity` | 身分証回収 |

**管理画面でできること**

- 公開リンクの発行・再発行・PIN ロック解除
- 申請一覧・詳細、**既存マスタとの重複候補（dedupe）比較**（一致/不一致の色分け）
- 承認（マスタへ反映）・却下
- 身分証ファイルのダウンロード（閲覧理由必須・監査ログ記録）

### 3.7 お知らせ `/operations/notices`

- 管理者 → スタッフへのお知らせ作成・配信
- スタッフモバイル側で未読バッジ表示

### 3.8 OCR・レシート解析 `/operations/ocr`

Paygate 関連の画像処理は、**2026年4月以降の大きな開発テーマ**です。現在は 1 画面に統合され、タブで切り替えます。

| タブ / 機能 | 内容 |
|------------|------|
| **Paygate スクリーンショット** | 取引一覧画面のスクショを OCR。複数行を一括抽出 |
| **精算レシート** | PAYGATE 精算レシートの OCR（端末識別番号・端末番号・金額内訳など） |
| アップロード済み画像 | 画像管理、再解析、入稿者表示、ファイル名整理 |
| 保存データ | 読取結果の確認パネル（画像＋データ並列）、編集・確定、信憑性％表示、絞り込み・並び替え |
| CSV との照合 | 本部 CSV と OCR 結果の突合 |
| 自己申告データとの比較 | sales_reports との比較（API 基盤あり） |

**外部アップロード（Ver.0.11.0〜）**

- 管理画面から**共有リンク**を発行（有効期限：日数 or カレンダー指定）
- ログイン不要の公開ページ `/public/ocr-upload` から最大 5 枚アップロード
- 画像種別は OCR で自動判別、入稿者名は必須

**在庫照合（Ver.0.10.0〜、精算レシートのみ）**

- 実在庫（opening / closing）の入力
- OCR 取引数との照合バッチ実行
- 調整理由（adjustment_reason）の記録
- 詳細仕様: `docs/spec/OCR_INVENTORY_RECONCILIATION_SPEC.md`

### 3.9 監査ログ `/audit-logs`

- 単価変更・再計算・請求発行・支払確定・締め/解除・登録申請・ファイル閲覧など、主要操作の履歴検索

## 4. スタッフモバイル（staff-mobile）— 実装済み機能

| 画面 | パス | できること |
|------|------|-----------|
| 本日 | `/today` | 今日のアサイン確認、**出勤 / 退勤打刻** |
| スケジュール | `/schedule` | 月次予定一覧、**参加可 / 辞退** の返信（未返答バッジ付き） |
| 稼働可否 | `/availability` | 日別の事前予定入力（4択: 終日OK / 15時〜OK / 不可 / 要相談） |
| 実績 | `/actuals` | 今月の確定実績一覧 |
| 経費 | `/expenses` | 経費申請（領収書添付）、今月の申請一覧 |

| 個人設定 | `/settings` | 曜日デフォルトの稼働可否、スキル資格フラグ、**プッシュ通知**の設定 |

**プッシュ通知**

- ブラウザ通知の許可・購読管理
- 工程別の進捗表示、拒否時の解除手順ガイド
- 運用: `docs/ops/PUSH_NOTIFICATION_RUNBOOK.md`

## 5. バックエンドの中核機能（画面の裏側）

これらは API として実装済みで、上記画面から利用されています。

| 領域 | 実装内容 |
|------|---------|
| 認証 | JWT（ログイン・パスワード変更・ロール別権限） |
| 単価 | 優先順位解決（ロック単価 → 案件単価 → ルール → デフォルト）、確定時スナップショット保存 |
| 時間計算 | 丸め・休憩・深夜割増（案件設定に従う） |
| 締め処理 | 仮締め（解除可）/ 本締め（二者承認）、解除回数上限 |
| 再計算 | プレビュー付き。本締め後・発行済み帳票紐付け実績は除外 |
| 集計 | 予定 vs 確定の区別、canceled / invalid の除外 |
| PDF | 請求書・支払明細（日本語フォント対応、版管理） |
| メール | 週次リマインド、承認依頼、エスカレーションなど 7 種テンプレート |
| スケジューラー | 週次催促メール、月次請求生成など（`scripts/scheduler_runner.py`） |

| 確認項目 | 結果 |

- `scripts/legacy/kintone/` — 旧 `kintone_service` 等

- `kintone_app/` / `docs/kintone/` — アーカイブ（[docs/kintone/README.md](kintone/README.md) 参照）

## 11. まとめ（クライアント向け一言）

**いま使える中核**は、案件〜シフト〜アサイン〜実績（CSV/打刻）〜請求・支払・締めの**月次業務一式**、スタッフ向けの**出退勤・予定返信・稼働可否・経費・通知**、および**公開登録フォーム**と**Paygate OCR（在庫照合・外部アップロード含む）**です。いずれも **admin-web / staff-mobile / API 上で完結**します。

**これから**は、販売台数報告・案件タスク・簡易 PL・個人成績など、計画書 Phase 2 以降の分析・現場報告系が主な拡張候補です。フィードバック再開時に、優先度のすり合わせに本書をご利用ください。
